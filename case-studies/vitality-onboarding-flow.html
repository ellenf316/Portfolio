Content design case study

Vitality Onboarding Flow

Vitality is a health behavior change program built around a companion app. As a B2B2C company, Vitality sells the program to health insurance companies and corporate wellness programs, who in turn provide it to their employees and customers — so the end audience is general-population consumers. When a new member joins, onboarding requires them to connect the Vitality app to Apple Health before they can start completing healthy behavior challenges.

I was asked to update the copy on the screens that walk a new user through connecting their Apple Health app to Vitality, so they can start getting rewarded for their physical activity.

Option 01

Connect + activate, inside onboarding

Health-app connection and challenge activation both happen during onboarding, leaving the surrounding flow as-is. Two moments needed copy: what a user sees if they try to skip or back out of setup — a screen reused across both options — and what they see if their phone's motion permissions are already off.

A user tries to skip or back out of setup

Friction

What changed — the placeholder gave no real reason to reconsider. The rewrite states one concrete consequence instead of a placeholder, and names each button by what it does — connect now, remind later, or opt out — rather than answering an implied yes/no question.

Content noteI don't think we should include the part about being able to change this in "Wellness Devices and Apps" later. Users won't remember it, and they're more likely to actually read the consequence line above if it stands alone.

Motion & Fitness permission is off

Friction

What changed — this system dialog's body copy was still a greeked placeholder. The rewrite leads with the payoff — what saying yes gets the user — instead of only restating the data being requested, which the title already covers.

Option 03

Connect the health app only

A narrower flow: onboarding only asks the user to connect Apple Health, and the challenge activates on its own once that's done. The existing product marked the finish line with two slightly different screens.

Confirmation screen

Confirmation

What changed — the product actually had two versions of this screen ("almost there" and "all set," worded slightly differently) for what's meant to be the same moment. The rewrite states completion plainly and names the reward mechanic (Active Challenges) instead of only describing what happens on a specific date — so the language stays consistent no matter which state a user lands on.

CTA options considered: Go to account · Go home · Done · Continue · OK

Design noteMake the date stand out — right now it sits in plain body text with no visual weight, in a line that's otherwise all a user needs to read.
